## Confounds and blockers

### B1 — The causal change is not yet singular (**Critical**)

The proposal names “execution schedule” as the changed variable but also asks
to diagnose cache/position/mask and rejection/correction semantics. A run that
changes schedule, cache transactions, and verifier logic together cannot say
which mechanism caused a divergence. Instrumentation can be diagnostic, but it
must not silently patch runtime semantics in the same arm.

**Minimum repair:** pre-register separate diagnostic arms: (A) target-only
singleton versus target-only block-shaped execution with no drafter; (B) the
published speculative path with state tracing only; and (C) a cache/rollback
round-trip negative control. No runtime patch, quantization change, or drafter
change may be bundled into this probe.

### B2 — Reproduction identity is incomplete (**Critical**)

The published drafter SHA-256 and exact v21/v22 flags are still missing. The
runtime lineage alone does not identify the built executable, compiler/CUDA
environment, backend, thread/device split, sampler flags, or model placement.

**Minimum repair:** attach target and drafter file hashes, binary/source hash,
compiler/CUDA/driver versions, device split, tokenizer, all decoding/runtime
flags, and the exact command/working directory before approval. If the drafter
hash or flags cannot be recovered, mark the published-path arm
`non-reproducible` and limit the probe to target-only state localization.

### B3 — The baseline is not yet a fresh, mechanically checked oracle (**High**)

The old target-only receipt is the stated oracle, but the proposal does not
require a fresh replay under the exact pinned binary before tracing the
speculative path. A target-only mismatch would confound every later conclusion.

**Minimum repair:** run target-only greedy replay first, twice from clean
processes, and require identical token IDs and output lengths to the preserved
oracle on all six prompts. Stop if this negative control fails.

### B4 — The first-divergence trace needs a state contract (**High**)

“Hidden/logit deltas” and “cache checks” are too broad to audit. Without a
fixed comparison point, the trace can find a numerical difference without
showing whether it is causal or merely expected from quantization.

**Minimum repair:** at each first divergence record prompt/cycle/position,
committed prefix, proposed and target token IDs, target top-1/logit summary,
target-state shape and dtype, mask/position IDs, cache state before/after
commit/rollback, correction token, and a deterministic replay identifier.
Compare the speculative next-token state with a fresh singleton target call
from the same committed prefix.

### B5 — The queue/lifecycle gate is incomplete (**High**)

The queue requires a named card and per-experiment critique before
`ready-needs-approval`; neither is linked for PLAN-001. The literature gate is
also stale relative to the reviewed notes. This critique record cannot repair
those control-plane links outside `experiments/critique/`.

**Minimum repair:** create/link the card and this pre-run record in the
program critique index, reconcile the LIT-001 status with its canonical notes,
and specify the terminal receipt directory plus cleanup/device-state fields.

## Minimum controls before CEO approval

1. **Target-only stability:** clean-process singleton replay twice; then a
   target-only block-shaped replay using the same prefix/positions. No drafter.
2. **Cache transaction control:** force an accept, a rejection at each tested
   proposal position, and a correction/rollback; after each commit, compare
   the next target logits with a fresh singleton call from the committed
   prefix.
3. **Mask/position control:** verify anchor, block mask, absolute positions,
   EOS handling, and cache lengths independently of drafter logits.
4. **Speculative trace:** run the published path only after controls 1–3 pass;
   capture the first divergence and the complete state contract in B4.
5. **Determinism:** pin greedy sampler, seed, threads, backend, device split,
   context, prompt order, and output-token budget; repeat the divergent prompt
   once to establish reproducibility.
6. **Receipt/cleanup:** write a compact receipt with commands, hashes, control
   outcomes, unknowns, no-heldout statement, task-owned process cleanup, and
   final device state. Do not copy model binaries or large traces into Git.

## Exactness, quality, and speed boundaries

**Exactness contract.** The probe may establish only six-prompt, strict-greedy,
token-by-token identity under the pinned runtime if every target-only control
passes and the oracle receipt is linked. It must not use `lossless`,
`equivalent`, or general runtime-exact language for a partial trace or a
target-content match.

**Quality contract.** No task/output-quality claim is in scope. Approximate
content matches, if recorded, are a separate diagnostic field and cannot
substitute for token identity.

**Speed contract.** No speedup claim is in scope. Timing may be omitted or
reported as diagnostic instrumentation only; the six-prompt trace is not a
matched serving benchmark and instrumentation may perturb latency.

**Data boundary.** Use only the six frozen diagnostic prompts and target-only
oracle references. Do not open training or sealed held-out data, and do not
select a model or proposal length from this probe.
